# Selected-Model Renderers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the GLM-5.2-only oracle into one unified, vLLM-derived text preprocessing oracle with independently selectable profiles and layered reproducible baselines for DeepSeek V3/V3.2/V4, Kimi K2.6, GLM 5.1/5.2, and MiniMax M2.7.

**Architecture:** A strict `ModelRegistry` resolves request aliases to immutable `ModelProfile` records, which select either the extracted HF renderer or an extracted DeepSeek-specific renderer. `TextOracle` remains the single public entry point and emits one versioned result contract. Asset, coverage, corpus, and result manifests make every upstream file and generated byte traceable.

**Tech Stack:** Python 3.11+, Pydantic 2.12.5, Transformers 5.13.1, Tokenizers 0.22.2, Jinja2 3.1.6, pytest 8.4.2, fixed vLLM v0.26.0 commit `568afb3a13806beb53bb2e6bd518269357b237c0`.

## Global Constraints

- Never load model weights or require GPU/PyTorch.
- Never download or decode image, audio, or video payloads.
- Pin every official model repository to an immutable revision and verify every asset SHA-256.
- Unknown aliases, missing assets, routing drift, and unauthorized generic fallback are hard failures.
- Preserve the existing GLM-5.2 request and result corpus while migrating it to the profile layout.
- Default tests run core tests only; model assets are touched only by explicit `--model`, except `--model all`.
- Handwritten results contain full token IDs; combinatorial and UltraChat results contain rendered text, counts, and hashes.
- UltraChat gzip output must be byte-for-byte deterministic.

## File Structure

- `src/vllm_text_oracle/profiles.py`: immutable model profiles, aliases, capabilities, and registry resolution.
- `src/vllm_text_oracle/errors.py`: stable processing stages and typed internal failures.
- `src/vllm_text_oracle/assets.py`: offline asset loading and integrity verification.
- `src/vllm_text_oracle/oracle.py`: unified orchestration and result conversion.
- `src/vllm_text_oracle/renderers.py`: renderer protocol and dispatcher.
- `vendor/vllm/extracted/deepseek_v32_*.py`: minimal DeepSeek V3.2 tokenizer, encoding, and renderer closure.
- `vendor/vllm/extracted/deepseek_v4_*.py`: minimal DeepSeek V4 tokenizer, encoding, and renderer closure.
- `models/profiles.json`: machine-readable official repositories, revisions, assets, and renderer assignments.
- `vendor/vllm/coverage.json`: upstream-to-extracted-to-profile-to-test mapping.
- `tests/model_cases/<profile>/*.json`: per-model focused golden inputs and expected values.
- `tests/test_profiles.py`, `test_model_selection.py`, `test_asset_integrity.py`: core profile behavior.
- `tests/test_deepseek_v32.py`, `test_deepseek_v4.py`, `test_hf_profiles.py`: renderer parity.
- `tools/fetch_model_assets.py`: checked, resumable official asset acquisition.
- `tools/generate_results.py`, `tools/verify_results.py`: model-selective layered baseline commands.
- `data/results/<profile>/`: committed per-model baseline shards and manifest.
